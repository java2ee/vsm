Требование к разработке WEB клиента

Этот документ описывает общие требования разработки WEB клиента.

1. URL приложения

Приложение может быть опубликовано как в корневом контексте сервера, так и иметь свое собственное имя контекст. Имя контекст, по сути, явлется именем приложения. На одном WEB сервере может эсплуатироваться множество различных приложений, каждое в своем контексте. На одном WEB серевре может быть запущено множество копий одного и того же приложения в разных контекстах (с разными именами).

Примеры URL ROOT контекста 

http://hmt.funsys.ru:8080/
https://hmt.funsys.ru:8443/

Примеры URL при собственном имени контекста, имя контекста vsm 

http://hmt.funsys.ru/vsm/
https://hmt.funsys.ru/vsm/

2. Оносительные пути

Все пути статических и динамических ресурсов WEB клиента должны быть только относительными. Путь ресурса должен строиться относительно индексной страницы index.html

Примеры
Полный URLОтносительный URI
https://hmt.funsys.ru/vsm/index.htmlindex.html
https://hmt.funsys.ru/vsm/api/v1/listapi/v1/list
https://hmt.funsys.ru/vsm/swagger-ui/index.htmlswagger-ui/index.html

В среде разработки (IDE) WEB клиента, например в Visual Studio Code, существует возможность в конфигурации проекта задать имя контекста приложения и настроить параметры прокси сервра для доступа к внешнему серверу приложений.

Пример настройки проекта WEB клиента на основе JavaScript-фреймворка VUE (фрагмент). 

...

export default defineConfig({
  base: '',

  ...

 server: {
    port: 5174,
    proxy: {
      '/rest': {
        target: 'http://localhost:8080/', // The address and port of your backend server
        changeOrigin: true,
        rewrite: (path) => path.replace(/^\/rest/, '/backend/rest'), // Optional path rewrite
      }, 
    }
  }
})

...

Если фреймворк WEB клиента не имеет подобных настроек, то можно воспользоваться внешним сервером Nginx.

3. конфигурационные параметры WEB клиента

Если при реализации WEB клиента требуется наличие каких либо конфигурационных параметров, то они должны прописываться в конфигурационным файле сервера приложений и запрашиваться WEB клиентом через API сервера.

4. Сборка приложения

Сервер (backend) и WEB клиент (frontend) при сборке компануются в один файл приложения (WAR, EAR) и в дальнейшем запускаются под упралением любого WEB сервера спецификации Java 2 EE.
