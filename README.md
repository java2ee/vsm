# Сервер приложиния ВСМ

## Выбор стека технологий

В качестве фреймворка приложения выбран вреймворк **"Avalanche - application framework for Java"**,
который обладает функциями не имеющих аналогов в мире. Разоработанное на его основе ПО в эксплуатации
можно настроить под требования любого заказчика больших, с штатом IT специалистов c разделением ролей
между ними и имеющих в эксплуатации принятые решения по обеспечению отказоустойчивости и безопасности,
и малых, у которых в штате небольшое число IT специалистов, отвечающих за сразу все области IT. У таких
заказчиков, как правило нет устоявшихся отказоустойчивых схем эксплуатации. Таким заказчикам можно
предложить откаустойчивые схемы на основе фреймворка **"Avalanche - application framework for Java"**.

Различные конфигурации для больших и малых закачиков не влияют на программный код разработанного приложения.

Различное ПО на основе вреймворка **"Avalanche - application framework for Java"** можно запустить на одном
хосте, на множестве узлов с разделением нагрузки различного функционала системы между узлами, на множестве
узлов с дублирующимиузлами отдельного функционала, в программном кластере на множестве узлов, в любой
другой схеме, принятой у заказчика, создающей отказоустойчивость за счет использования доруго внешнего ПО.

Различное ПО на основе вреймворка **"Avalanche - application framework for Java"** обладает высокой,
модифицируемостью. Вплодь до того, что функционал приложения может быть модифицирован без модификации
эксплуатируемого кода. Высокая модифицируемрость ПО, позволяет оперативно реагировать на вновь возникющие
требования в процессе вего жизненного цикла информационной системы с минимальными затратами различных
ресурсов (трудовых, финансовых, вренных и т.п.). Новые требования порой возникают весьма неожиданно и могут
быть ограничены во времени реации на них. К таким требованиям можно отнести изменение законадальства и
нормативных актов, реорганизации структуры предприятия, изменений технологических процессов и т.д.   
   
## Выбор СУБД

Фреймворк **"Avalanche - application framework for Java"** может работать с любой БД. Для обеспечения простоты
развертывания и демонстрации работоспособности выбрана СУБД H2, которая запускается прямо в приложении.
При переходе на другую СУБД, например Postgres, достаточно исключить из конфигурации объекты приложения,
запускающие H2, и сконфигурировать внешний источник данных.

## Структура приложения

Приложение состоит из серверой и клиенских частей, мобильно приложение и WEB клиент управления предметной областью.
Сервераная и клиенская часть собираются в один **WAR файл**, который может быть запущен под управлением любого
Java WEB сервера. Приложение имеет два конфигурационных файла непосредственно приложения и системы ведения журналов
приложения. Опционально используется файл конфигурации консоли СУБД H2. Все файлы конфигурации достаточно скопировать
в каталог конфигурационных файлов WEB сервера, в катлок **conf** сервера Tomcat или каталог **standalone/configuration**
сервера WildFly

## Конфигурационные файлы 

При	меры конфигурационных файлов находятся в каталоге **cfg** проекта. Отдельно для Tomcat приведен пример крнфигурации
контекста **context.xml**. Файл **.h2.server.properties** может не отображаться в среде разработки 

```
cfg/tomcat/context.xml    - пример конфигурации контекста
cfg/.h2.server.properties - файл конфигурации WEB консоли H2 (опционально)
cfg/vsm-config.xml        - пример файла конфигурации приложения 
cfg/vsm-log4j.xml         - пример файла конфигурации системы ведения журналов приложения log4j
```
 
## Процедура установки

### Предварительно усановленное ПО

Предварительно на хосте должно быть установлено следующее ПО:

* JVM версии 17 или выше, или руководствоваться требованиями к JVM выбранного Java WEB сервера.
* Java WEB сервер, например Tomcat 10 или выше или WildFle 36 или выше
* Библиотка JDBC драйвера выбранной СУБД, напрмер **h2-2.4.240.jar**. Библиотека должена быть скапирована в каталог 
 **lib** WEB сервера Tomcat либо добавлена в виде модуля WEB сервера WildFly  

Выполнить требуемую настройку WEB сервера, например прописать переменную окружения **JAVA_HOME** в командные файлы WEB
сервера. И проверить успешность его запуска

### Установка приложения

* Скопировать конфигурационные файлы приложения в каталог конфигурационных файлов WEB сервера. При необходимости внести в них изменения, например изменить имя БД, изменить JDBC драйвер СУБД, указать свои параметра учетной записи БД.
* Скопирвать файл конфигурации **.h2.server.properties** в каталог конфигурационных файлов WEB сервера (опционально). При необходимости внести изменение, например имя БД.
* Скопировать файл контекста **context.xml** в каталог **conf/Catalina/localhost** (опционально для Tomcat), Внести в него
 необходимые изменения, например настроить собствнный источник учетных записей (REALM) и переименовать этот файл. Имя этого файла должно совпадать с именем **WAR** файла, если **WAR** файл имеет имя **vsm.war**, то файл конфигурации контекста должен иметь имя **vsm.xml**. Для других Java WEB серверов необходимо сконфигурировать источник данных и источник учетных записей 
 пользователей в административной консоли сервера.
* Скопирвать файл **vsm.war** в каталог **webapps** WEB сервера Tomcat или выполнить деплой приложения через административную
 консоль WEB сервера.
